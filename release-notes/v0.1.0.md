# buia 0.1.0

First release of BUIA (*Bottega Unipersonale d'Intelligenza Artificiale*): a local, standalone personal assistant for Windows and Linux. Based on llama.cpp (CUDA, router mode) behind a small FastAPI agent and a web UI, it can be run by Docker Compose on your own PC with an NVIDIA GPU. Your chats and notes stay on your PC; it goes online only to download models and container images and, unless you turn it off, to search the web.

## What is in it

- Chat with GGUF models you download from Hugging Face in Settings, with a fit check per quant. Replies stream and chats are saved as JSON files.
- File tools on your buia folder and on a read-only notes folder (an Obsidian vault if you point `VAULT_PATH` at one). The assistant keeps its memory in `BUIA.md` and `memory/`.
- Web search and page reading through a bundled SearXNG with guards against prompt injection from notes and web text. `WEB_ACCESS=off` turns them off.
- Optional image and video generation: stable-diffusion.cpp with `-Sd` (presets Z-Image Turbo, Wan 2.1 and Wan 2.2; any Hugging Face repo of a supported family can be added) and CogVideoX 2B with `-CogVideo`. A video dashboard shows a progress bar.
- A password-protected web UI with themes, reachable from a phone over Tailscale with `-Tailscale`.

## Install

Windows 11 with Docker Desktop (WSL2 backend) and its NVIDIA GPU support, or Linux with Docker Engine, the Compose plugin and the NVIDIA Container Toolkit; a driver recent enough for CUDA 13 (580 or newer on Linux), and Git. Clone the repository and run `install.cmd` (Windows) or `./setup.sh` (Linux, installs and updates); the README has the steps. The release number is in `core/agent/VERSION` and in the answer of `/api/health`; please include it in bug reports.

## Known limits

- Linux support is new in this release: `setup.sh`, the compose file and the agent container running as your user are covered by tests and CI, but the whole stack with a GPU had not been run on Linux by the author when this was written. SELinux hosts (Fedora, RHEL), rootless Docker and Podman are untested.
- Developed and measured on one machine (RTX 5050 Laptop GPU, 8 GB VRAM, 32 GB RAM). The sd image is built for RTX 50 series (compute capability 12.0); another card needs `SD_CUDA_ARCHITECTURES` in `core/.env` (`setup.sh --sd` sets it), see the README.
- Not measured yet: peak VRAM and RAM of CogVideoX, and the fit verdicts of Wan 2.2 TI2V 5B, FLUX.1 schnell, SDXL and SD 1.x.
- Except for the agent on Linux (it runs as your user), no service sets `user:`, and the images built here (agent, cogvideo, sd) have no `USER` line, so their processes run as root. The containers can reach only what Compose mounts into them.
- The `sd` image (built with `-Sd`) is not pinned: it starts from `nvidia/cuda` tags and installs packages with apt, so a rebuild can change it. The llama.cpp, SearXNG and Python base images are pinned by digest and the Python dependencies are hash-locked. The README says how to move a pin.
- One shared password, meant for `localhost` and your own tailnet. Never expose it with `tailscale funnel` or to the open internet. Five wrong passwords lock the login for everyone for a minute, so anyone who can reach the login page can keep you out.
- `update.cmd` and `setup.sh` run `git pull --ff-only`: a downloaded zip can be installed but not updated. Clone the repository instead.
